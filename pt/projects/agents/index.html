Agentes de IA em Produção

Eu construo o ecossistema, as ferramentas, integrações e orquestração que dão a um modelo fundacional a capacidade de agir de verdade no mundo real.

  • 8 agentes de IA em produção: um control plane, que escreve as PRs de engenharia e audita a infraestrutura, e sete dentro de vendas, sucesso do cliente, suporte, marketing, projetos, alertas de incêndio e liderança.
  • Uma pessoa revisa e mescla toda PR. A autonomia do agente é de autoria — ele abre o pull request, alguém do time faz o merge.
  • Self-hosted em servidores nossos, sobre o Hermes — o runtime de agentes open-source da Nous Research.

Os agentes

O control plane carrega os dois números duros aqui embaixo. Os outros sete rodam uma área cada um, ao lado da pessoa que responde por ela.

Escrevendo código

0 PRs escritas e 0 issues fechadas pelo agente, nos primeiros 3 meses. Uma pessoa revisou e mesclou cada uma.

Cuidando da infraestrutura

Cortou 0% dos custos de infraestrutura AWS. Um watchdog checa cada perfil de agente a cada 15 minutos.

Ao lado dos times

Sete agentes de área — vendas, sucesso do cliente, suporte, marketing, projetos, alertas de incêndio, liderança. Cada um entrega o briefing da manhã pra pessoa que responde por aquela área.

O que faz a delegação ser real

Um agente que abre pull request em repositório de produção precisa de mais que um bom modelo. Isso é o que teve que existir antes.

Revisão Humana

O agente abre a PR; uma pessoa revisa e mescla. Job agendado abre a issue crua, sem etiqueta de projeto, pra obrigar a triagem humana.

Governança Estratégica

Revisão semanal de OKR cruza o board com os KRs do trimestre e aponta épico sem KR vinculado.

Pipeline de Entrega

Backlog roda em GitHub Projects — boards de Sprint e de Épicos — planejamento, issue e PR no mesmo sistema onde o código vive.

Self-Healing

Uma auditoria cognitiva revisa a própria memória e uso de skills dos agentes, abrindo issue contra si mesma quando precisa se refatorar.

Estado como Código

Configuração e memória de runtime sincronizam de volta pro GitHub via PR automático, duas vezes por semana.

Vigilância de Segurança

Uma auditoria de backend varre vulnerabilidades toda manhã de dia útil; uma auditoria de web separada roda semanalmente. Só achado maior que zero avisa o time no Telegram.

Auditoria Recursiva

Toda segunda-feira, uma rotina dedicada revisa todos os outros jobs agendados de cada perfil de agente — agenda perdida, falha silenciosa — antes que se acumule.
