Hermes Workforce

Each department of a company gets an agent that knows what it owns. Talk to any of them: if the request isn't theirs, they hand it to the owner, with a trail and a human approving.

No second orchestrator beside Hermes. One hook, one tool, the native kanban.

Read the charter View on GitHub

The bots should know

People should not need to know which bot handles what. Telling a bot what is not its job is half the problem: without a way to pass the request on, it either solves it anyway or says it escalated when nothing happened.

01 — Charter

A company charter,
injected every turn

A fleet.yaml defines departments, what each owns, what it does not, and where it escalates.

The pre_llm_call hook finds the department by ctx.profile_name and appends it to the turn. No charter, no behavior: the plugin stays inert.

# fleet.yaml
departments:
  support:
    owns:
      - customer tickets and account questions
      - known issues covered by playbooks
    does_not_own:
      - bugs that need a code change
    escalates_to: tech
  tech:
    owns:
      - bugs, incidents and integrations
    escalates_to: leadership
02 — Handoff

A kanban task,
parked for a human

handoff_task opens a task on Hermes' native kanban for the department in escalates_to, carrying the source reference.

It is born blocked. A human there approves with hermes kanban unblock or takes it. The same ticket twice returns the same task.

// thin wrapper over kanban_create
assignee         tech
status           blocked   ← human approves
idempotency_key  workforce:tech:<ticket>
source           <ticket id>
from             support

// if core grows, the plugin gets thinner,
// it does not break.
03 — Ownership

Ownership follows the problem.
Tools follow the work.

A department can use another's tools to finish its own work: tech closes the support ticket for the bug it just fixed.

When the problem itself belongs to another department, it hands off. owns is responsibility, not access.

◇ ◇ ◇
First case: support → tech

Hand it to the owner

Today, when a ticket leaves support's reach, a person escalates it in a humans-only chat. The bot that talks to the support team has no way to say "this one is tech's".

With the plugin, the support agent recognizes the problem is not its own, opens a kanban task for tech with the ticket ID, and tells the user it is waiting for human approval. The ticket ID is the key of the trail.
